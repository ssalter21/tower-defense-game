// The playfield: one hex corridor, exactly one hex wide, never branching, and
// the tier every hex of it stands at. It folds, and it climbs.
//
// '.' ground   '#' corridor   'S' the entrance   'E' the exit
// 'a' the ground, then a letter per HALF BLOCK of height above it, up to 'i'.
//
// HALF BLOCKS, NOT BLOCKS. A level used to be a whole block and this board was
// written 'a' 'b' 'c'; it now reads 'a' 'c' 'e', which is the same three
// heights on a grid twice as fine. Nothing about it moved and no tower's reach
// changed -- Reach halved what a level is worth in the same change -- but the
// levels in between are now available to grade a slope with, and the odd
// letters here are the mark of a board that has not used them yet.
//
// A comment here starts with '//' rather than '#', because '#' is a corridor
// cell and sharing the marker would make a corridor beginning at column one
// vanish into a comment on some maps and not others.
//
// TWO BLOCKS AND NOT ONE. The first is the terrain, the second is the level of
// every hex of it, and they are the same shape or the file is refused -- a hex
// whose height nothing states is a hex the loader would have to invent one for.
// Levels are letters because this file holds no numbers at all, which is how it
// stays outside the decimal-point rule the numeric data files carry; a digit
// anywhere in either block is a load error.
//
// One row per line, one character per cell, so the map is diffable and an
// agent can write it. Rows are odd-r offset: ODD-NUMBERED ROWS ARE THE ONES
// SHIFTED HALF A CELL RIGHT, which is why the corridor's turns look like they
// step sideways, and why the odd rows are indented here -- the indent is
// decoration the loader strips, so that what is typed looks like the board it
// produces. The simulation converts the grid to axial (q, r) on load and never
// stores a cube coordinate; how any of it is drawn is a view question and does
// not reach here.
//
// THE OFFSET DECIDES WHERE A CORNER MAY GO, and this is the rule a hand drawing
// breaks first. A cell in an odd row touches the two cells above it at its own
// column and one to the RIGHT; a cell in an even row touches its own column and
// one to the LEFT. So a turn has to leave the other of that pair empty, or the
// cell it turns into touches three corridor cells and reads as a junction. A
// square-grid corner is one cell too tight here, every time.
//
// The loader asserts the corridor is well formed rather than trusting this
// comment: every corridor cell has one or two corridor neighbours, exactly
// two have one, those two are S and E, and the walk from S to E visits all
// 51 of them.
//
// Draw it: ./tools/render-map.ps1
