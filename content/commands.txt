# The command script: one whole run, decided in advance.
#
# THIS IS THE AUTHORED SOURCE OF content/run.commands, which is the record a run
# is actually played from. Compile it with tools/run-headless-match.ps1
# -Regenerate, which records the bytes, reads them back, plays them to the end
# and only then writes them -- so a script that cannot be played never becomes a
# file, and the committed record is one that provably came from a real run.
#
# Same rules as units.txt, ruleset.txt and upgrades.txt: integers only, no
# decimal point, comments free.
#
# ---------------------------------------------------------------------------
# THE ROW
#
#         build  wave   type-id count   type-id count  ...
#
# wave      : which round of the run this decision was made in, counted from
#             one. BUILD ROWS ASCEND STRICTLY BY WAVE and there is one of them
#             per round: a run plays them in the order they are stored, and two
#             decisions for one round is two runs written down as one. The
#             action rows below repeat their own wave, which is how they say
#             which build row they belong to.
# slots     : a type id and a count for each slot of the wave, in the order they
#             are filled. A SLOT'S POSITION IS ITS RELEASE ORDER: slot one's
#             creeps walk out first, slot two's fall in behind them, and the
#             wave is one column at one cadence -- one body every forty-five
#             ticks, from the first of slot one to the last of the last slot.
#             Writing the same slots the other way round is a different wave and
#             not a second spelling of one, so THE SLOTS ARE NOT SORTED AND NOT
#             ASSERTED TO ASCEND. They had to ascend by type id until #191,
#             which is what canonicalising an arrangement looks like while the
#             arrangement is not yet a decision.
#
#             A CREEP MAY FILL ONLY ONE SLOT OF A WAVE. That half of the old
#             rule stays: two slots on one creep is a slot spent twice on one
#             thing, and the same wave is spelled by putting the whole count in
#             one of them.
#
#             An EMPTY SLOT IS SPELLED 0 0, and it is a position rather than an
#             omission: what is not sent is banked at the ruleset's interest. An
#             empty slot takes no place in the column, so banking one closes the
#             gap rather than leaving a hole in the wave.
#
#             A ROW MAY FILL AS MANY SLOTS AS IT LIKES. Wave widths came out
#             with the anchor schedule in #179; what bounds a wave is the purse,
#             which is the only thing a player is spending against.
#
# ---------------------------------------------------------------------------
# THE ACTION ROW
#
#         place    wave  type-id  column  row
#         upgrade  wave  type-id  column  row
#
# What the round does to the board, under the build row of its own wave. Five
# fields either way, because an action names one cell and one type and there is
# nothing on it that repeats.
#
# place     : stand a new tower on an empty cell. It takes the next placement
#             ordinal, which is what the ending-board block down in
#             content/run-outcome.txt lists it under.
#
#             A TYPE SOME EDGE OF content/upgrades.txt POINTS AT MAY NOT BE
#             PLACED. It is reached by standing the rung below it and upgrading
#             into it, which is the one prerequisite this game has: a tier that
#             can be bought without the tier under it is not a tier, it is a
#             second row at a higher price.
# upgrade   : change the type of the tower already standing on a cell, keeping
#             its identity. IT PAYS THE TARGET ROW'S FULL PRICE. The ladder says
#             what may be placed and prices nothing, which is why an edge has no
#             cost column.
# cell      : the column and the row map.txt is written in, so a tower can be
#             placed by counting characters in that file.
#
# ACTION ROWS ARE NOT SORTED AND MUST NOT BE. Their order is meaning: a round
# may upgrade what it has just placed, and the placement ordinals fall out of
# the sequence. This is exactly the opposite of the wave slots above them.
#
# THE ORDER A ROUND PAYS IN IS THE ACTIONS, THEN THE SLOTS. A tower bought here
# is standing when this round's waves arrive, and the wave is bought out of what
# the towers left. A round whose towers ate its wave is refused whole rather
# than sent short, so the arithmetic below has to add up.
#
# ---------------------------------------------------------------------------
# HOW A ROW IS WRITTEN
#
# Every creep on the roster is sendable from wave one. There is no menu to read
# and nothing to unlock, so a build row is written against content/units.txt and
# the purse alone.
#
# THE SEED IS STILL PART OF THE SCRIPT even though it is not in this file: it
# draws the field of K each round is scored against, so the same decisions on
# another seed are a different run. The seed lives in the compiled record, where
# the replay gate can refuse a run that was never the one these decisions were
# made in.
#
# --field IS THE CANNED OPPONENT AND NOT A WAVE THIS RUN SENDS. The waves in
# this file are composed by its own build rows out of a purse; --field is the
# round the field of K is drawn from, and content/wave.txt -- a whole authored
# match, released over fourteen hundred ticks -- is refused there by name.
#
# ---------------------------------------------------------------------------
# WHAT THIS PARTICULAR RUN DOES
#
# Four rounds against the canned field, and it dies in the fourth.
#
# THE OPPONENT ACCUMULATES, SO THE PRESSURE CLIMBS FASTER THAN A WALL CAN. The
# field is a population recorded round by round now, and the stand-in in it buys
# content/field.txt's column once more every round: ten bodies in round one,
# twenty in round two, forty in round four. What a wall stops is close to a
# fixed NUMBER of creeps rather than a fixed share -- the committed six-tower
# defense kills twelve of a column whether the column is twenty deep or a
# hundred -- so what gets past is almost the whole of the increase. This run
# takes 100, then 190, then 265, and the fourth round's 330 is more health than
# it has left. The measurements are in
# docs/research/a-wall-kills-a-count-not-a-share.md.
#
# SO THE FILE IS FOUR ROWS, AND THAT IS THE RUN THIS ECONOMY SUPPORTS. A fifth
# build row could not be recorded at all: record-run plays a script to the end
# before it writes anything, and a round after this one is a round nobody was
# alive to play. What the run demonstrates is the ramp and the accumulation
# either side of it, which is what four rounds are enough for.
#
# THE WALL IS FOUR ARCHERS AND IT GOES UP ONE A ROUND. The corridor crosses the
# map four times -- east along row 1, back west along row 3, east again along
# row 5, west to the exit along row 7 -- and each ground row between them
# touches two of those crossings. So a tower on row 2 watches the first and the
# second, one on row 4 the second and the third, and one on row 6 the third and
# the fourth. Three of them stacked around columns six and seven is four
# separate chances at every creep that walks past, which is worth more than four
# towers spread thinly enough that each sees a creep once. The fourth, at column
# four, watches the western turn instead: the single hex at row 4 where the
# corridor doubles back, and the stretch either side of it, which nothing at
# column seven reaches. It is the cheapest forty gold in the file.
#
# AND IT SENDS FROM ROUND TWO, BECAUSE BANKING NO LONGER PAYS. Waiting five
# rounds and spending the bank in one is the play against a field that never
# grows; against one that does, the rounds a run banks through are the rounds
# that kill it, and gold held at the end is gold that bought nothing. So every
# round after the first buys creeps as well as a tower.
#
# EVERY WAVE NAMES EVERY CREEP THE RUN HAS EVER BOUGHT. That is #207: a phase's
# slot lines are the whole of its round's wave, and the purse is charged only
# for the increase over the round before. Round three names the ten runners
# round two bought and pays for the ten it adds; round four names all twenty and
# pays for the minions alone. A line that named fewer of a creep than the line
# above it would be refused where it is read.
#
# THE LATE ROUNDS SPEND ON DEPTH RATHER THAN ON WIDTH. A count is released one
# body every forty-five ticks, so gold split across more columns arrives as more
# bodies per tick over fewer ticks and saturates the towers less;
# content/field.txt's header carries the measurements.

build    1   0 0
place    1  3   6  2
build    2   2 10
place    2  3   7  4
build    3   2 20
place    3  3   7  6
build    4   1 10  2 20
place    4  3   4  4
