# The upgrade ladder.
#
# ONE ROW SAYS THAT ONE UNIT FOLLOWS ANOTHER. A row names a source id and a
# target id, both of them ids in content/units.txt, and it means that a built
# source may be swapped for a target. That is the whole content of an edge: no
# tier number and no direction marker.
# Reasoning in docs/adr/0045-the-ladder-is-a-graph-not-a-list.md.
#
# THE KEYWORD SAYS WHICH CURRENCY BUYS THE EDGE, AND THERE ARE TWO.
#
#   upgrade  -- the target row's full `cost` column, in gold, out of the one
#               purse. Every rung below the top of a line.
#
#   capstone -- ONE CAPSTONE TOKEN AND NO GOLD AT ALL. A run is granted one at
#               rounds 3, 6 and 9 and can spend it on nothing else, so three
#               tokens meet nine capstones and which line reaches its top is a
#               decision. The target's `cost` column is still authored -- every
#               row has one -- and nothing charges it. That is why a capstone
#               is not priced by the damage rule and why no premium is authored
#               to compensate: scarcity is the schedule, not the price.
#               Reasoning in docs/adr/0062-a-capstone-costs-a-token.md, and the
#               design side in docs/roster.md's "What things cost".
#
# THE PRICE IS THE EDGE AND NOT THE ROW IT LANDS ON. Every capstone row below
# happens to be the top of its line, and nothing here says it has to be: a row
# reached along two edges could be a token up one and gold up the other, and it
# would cost what the edge that was climbed says. That is why the keyword is on
# the edge, and it is why a refusal names the edge rather than the row.
#
# THE KEYWORD IS WHY THIS IS ROW LAYOUT 2. The field count did not move -- a row
# is still a keyword and two ids -- but what the keyword column means did, and
# two files whose keyword means two different things under one layout label is
# the silent-misread class content/units.txt states the rule about. So the price
# joins the fold from layout 2, under the label `upgrade-ladder/2`, and a
# layout-1 file still reads and still hashes to the value it always did: one
# keyword, every edge in gold, which is what those files always said. A
# `capstone` row in a layout-1 file is refused rather than read.
#
# INTEGERS ONLY, AND NO DECIMAL POINT. Same rule as content/units.txt and
# content/ruleset.txt, same reason, and the same parser enforces it: a '.' or a
# ',' anywhere on a data line is refused before the line is even tokenised.
#
# ONE EDGE PER ROW AND THE ARITY IS FIXED AT TWO IDS. A row whose field count
# is not two is refused rather than read against shifted fields. Two rows naming
# the same target are how a diamond is stated -- two lines, not a wider one.
# What an edge costs is the keyword rather than a third id, so a second currency
# arrived without widening a row.
#
# THE TARGET ID MUST EXCEED THE SOURCE ID. Ids in units.txt ascend strictly down
# the file and are never reused, so a target above its source makes a cycle
# unstateable rather than something a walk has to detect. What it costs is real
# and worth stating: a rung can never be inserted BELOW an existing unit. A tier
# that ought to sit under a row already authored is a new row at a new id and the
# old one retired, exactly as a column change is a new layout.
#
# ROWS ASCEND STRICTLY BY (FROM, TO). Asserted and never sorted, which is what
# makes a duplicate edge a comparison against the row above rather than a lookup
# nobody performed. It is also what makes this file canonical, so that a ladder
# folds into the unit table's content hash the same way whoever typed it ordered
# the lines.
#
# A FILE WITH NO EDGES IN IT IS LEGAL -- a layout row and nothing else. A ladder
# with no edges folds nothing into the content hash, so a roster half-way through
# being authored still loads and every record made before this file existed stays
# replayable forever. Reasoning in
# docs/adr/0046-an-absent-ladder-folds-nothing.md.
#
# THE SIMULATION READS THIS FILE. It did not until #179, and the sentence that
# used to stand here said so; the anchor schedule was the only prerequisite the
# game had and this file was an annotation beside it. Deleting the schedule left
# the ladder as the one prerequisite there is, so a run is handed one and
# BuildPhase.Resolve asks it two questions. A UNIT SOME EDGE POINTS AT MAY NOT
# BE PLACED -- it is reached by standing the rung below it and upgrading into
# it. And WHAT DOES THIS EDGE COST, which is the keyword above and is the one
# place either currency's price is written down.
#
# WHAT THAT COSTS. A stored record is now retired by an edit to this file, the
# same way it is by an edit to content/ruleset.txt: a command stream carries a
# ladder hash in its header and the replay gate refuses a stream whose ladder
# has moved underneath it. That stamp is the third one a command stream has, and
# it replaced the anchor schedule's at the same offset -- which is what command
# stream format version 2 is the bump for.
#
# Nothing in a TICK LOOP can still observe an edge. What reads this file is the
# build phase, which is where a decision is priced and refused, and no further
# in. Reasoning in docs/adr/0045 and docs/adr/0046, both of which carry a note
# saying which of their sentences this overturned.
#
# WHICH CHECKS ARE FAULTS AND WHICH ARE NOTES. A whole-file pass walks the
# ladder against the roster and returns both. Neither refuses to load -- a
# half-authored roster has to stay runnable -- so the faults are what the build
# gate goes red on and the notes are printed for a person.
#
#   Faults, and there are two.
#
#     MIXED ROLES -- the two ends of an edge have different roles. A placed unit
#     that upgrades into a walking one is not a tier, it is a typo.
#
#     UNEQUAL ROADS -- two ids joined by more than one path where the paths are
#     not all the same length. A diamond whose sides differ is a ladder where
#     one route to the same tower costs fewer upgrades than another.
#
#   Notes, and there are three. Each is a design statement rather than a defect,
#   and none of them is ever judged.
#
#     ROOT -- a unit with no incoming edge. LEAF -- a unit with no outgoing edge.
#     FLAT OR FALLING PRICE -- the target's cost column is no higher than the
#     source's. It fires on a capstone edge too, and says so differently there:
#     on a gold edge it is what the upgrade costs, and on a capstone edge it is
#     how the damage rule scores a rung nothing charges gold for. Seven of the
#     nine capstones read flat, which docs/roster.md's cost section explains.
#
# ./tools/show-ladder.ps1 prints the edges, then the notes, then the faults, and
# always exits zero.
#
