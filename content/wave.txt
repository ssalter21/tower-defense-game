# The wave the skeleton's one match is fought against.
#
# Same rules as units.txt: integers only, no decimal point, comments free.
#
# Orders ascend by tick and then by type id, and are unique on that pair with
# repeats merged into a count. THAT ORDER IS ASSERTED, NOT SORTED ON LOAD.
# Sorting would stabilise iteration and leave two identical waves with two
# different sets of bytes, at which point content-addressing a wave stops
# meaning anything.
#
# A type id this file names that units.txt does not define is a load error,
# not a skipped row. Tolerating what you do not understand is right for a
# network message and exactly wrong for a replay, which would otherwise
# produce a confidently wrong result that still validates.
#
# A COUNT IS A COLUMN, NOT A PILE. The units of one order are released one
# every fifteen ticks, which is a rule the simulation owns rather than a number
# in this file -- so it is covered by the simulation version, and changing it
# changes replays. Releasing a whole order on one tick was the obvious reading
# and is the wrong one: units of one type share a speed and a route, so ten of
# them released together are one stack forever, and a stack is the single
# arrangement in which unit ordering cannot be observed at all.
#
# THE TICKS ARE TUNED, and two things are being tuned for. A Skeleton Scout
# order is placed while the Minion order before it is still walking, so the
# fast group visibly catches the slow one -- the first overtake in the
# committed run is at tick 347, which landmarks.txt beside this file carries
# because a real run reported it, not because anybody worked it out. And the
# last order is Minions rather than Scouts, so the tail of the match is the
# slowest thing on the map and the match lasts a hundred and eighty-nine
# seconds rather than ending the moment the quick ones are dealt with.
#
# EVERY TICK BELOW WAS MULTIPLIED BY THREE ON 8 AUGUST 2026, when the roster
# was signed and the clock slowed by the same factor. It had to be, and this is
# the one file the roster ticket authorised to move: durations and speeds were
# dilated in units.txt but a tick in this file is measured against the clock
# those durations are counted in, so leaving them alone would have compressed
# the whole wave threefold against a defense firing at a third of the rate.
# Measured rather than reasoned -- left alone the leak went from thirteen of
# forty to twenty-five, and dilated it lands at seventeen.
#
#   ONE PART OF THE DILATION COULD NOT REACH THIS FILE. The fifteen-tick
#   release cadence above is a simulation constant and not a number here, so a
#   column of ten still empties over a hundred and fifty ticks while its units
#   walk a third as far in them -- which leaves columns three times denser in
#   space than they were. That is a real change in wave shape, it is not a
#   defect in these ticks, and it cannot be undone from content: the constant
#   is covered by the simulation version and moving it would retire every
#   stored replay.
#
#       tick  type  count  corridor
#
# tick     : ticks after the wave starts
# corridor : which lane; the skeleton has one, and it is zero
