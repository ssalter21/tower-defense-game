# The ruleset.
#
# EVERY NUMBER THE RULES ARE MADE OF, and not one of them in code. The damage
# matrix, the armour expression, the floor, the purse, the offering and the
# scouting price all live here, so tuning any of them is an edit to this file
# and never a compile -- and a sweep can sweep them the way it already sweeps a
# map.
#
# Same rules as units.txt: integers only, no decimal point, comments free. The
# content hash folds the parsed integers in FIELD ORDER rather than the bytes,
# so reindenting a column, rewrapping this comment or converting the line
# endings moves nothing, and changing one number moves it.
#
# EVERY ROW IS REQUIRED AND NONE MAY APPEAR TWICE. A rule this file does not
# state is refused by name rather than defaulted: a default is a number nobody
# authored, folded into the content hash as though somebody had.
#
# THESE NUMBERS ARE PROVISIONAL BY CONSTRUCTION. They are priced against the
# one-hex corridor, which is the only board that exists. Being wrong about one
# of them costs this file. Being wrong about which of them are parameters costs
# a sweep across every call site, which is why all of them are here.
#
# ---------------------------------------------------------------------------
# HOW A SHOT RESOLVES
#
#         matrix  attack   swift  armoured  arcane
#
# Nine percentages, held as one flat array indexed cells[attack * 3 + armour]
# and read as "this attack type deals this much of a hit to that armour type".
# EVERY ROW AND EVERY COLUMN IS A PERMUTATION OF THE SAME THREE CELLS, and a
# matrix that is not one refuses to load -- that property is what makes no
# attack type globally better and no armour type globally tougher. The three
# rows are authored in attack-type order, so a missing or repeated one is a
# comparison against the row above rather than a lookup nobody performed.
#
# 140 against 70 moves shots-to-kill by exactly double: a real read, and never
# an unwinnable draw.

matrix     pierce    140    70       100
matrix     impact     70   100       140
matrix     magic     100   140        70

#         armour  coefficient  denominator
#
# The armour expression, as the two integers its shape is made of:
#
#     dealt = (base + bonusVsTag) * cell / (denominator + coefficient * armour)
#
# ONE MULTIPLY, ONE DIVIDE, EVALUATED ONCE. The same algebra written as two
# divisions truncates twice and is a different function on nearly half of all
# inputs. A coefficient of 1 against a denominator of 100 is what makes a point
# of armour read as one percent of base effective health per point, and a cell
# of 100 the identity.

armour          1          100

#         floor  damage
#
# The least a hit may deal, applied after the whole expression. No combination
# of type, armour and counter deletes a hit entirely.

floor           1

# ---------------------------------------------------------------------------
# THE PURSE
#
#         interest  percent  cap
#
# What unspent gold earns a wave, ROUNDED UP -- one gold banked earns one and
# never nothing. Leaving a wave slot empty is an investment rather than waste,
# and every purchase is measured against it.
#
# The cap is the most interest a single wave may pay, and ZERO IS NO CEILING.
# Compounding is bounded by the round cap and by nothing else, so a run whose
# round cap has been lifted against a ruleset with no ceiling here is refused
# before it starts rather than discovered later as an exploding number.

interest       10         0

#         income  gold
#
# The flat base a wave pays. It is paid whether or not there is a field to be
# measured against, which is why a run resolves before there are ghosts.
#
# IT BUYS BOTH HALVES OF THE BOARD, WHICH IS WHY IT IS NOT A HUNDRED. A member
# of the canned field stands the six towers of content/defense.txt for nothing
# and sends content/field.txt's hundred gold from behind them; a run opens on an
# empty board and pays for its wall and its wave out of this one row. At a
# hundred, all twenty-two rows of content/sweep.csv read win_rate_bp 0 and
# cost_efficiency_dealt_per_100_gold 0 to 5 -- a run's offense landed under two
# percent of what the field's own waves landed on it, which is a report that
# separates nothing and a build phase nobody has a reason to think about.
#
# 168 IS WHERE THAT WAS MEASURED BACK. Swept at the committed shape, the roster
# wins three, three, four, five and seven of every eight runs and its cost
# efficiency spreads 18 to 39, which is the separating column content/field.txt
# was calibrated to produce; at thirty-two runs a creep the same five come in
# between 44 and 94 percent and three of them sit inside the 41-to-66 band that
# file's header records. The window is narrow and it was walked: at 160 the
# scout still wins one run in eight, and at 200 four of the five win every run
# they play. Three other first seeds put the five in the same order.
#
# THE FIELD WAS THE OTHER LEVER AND IT CANNOT REACH THIS. What a run gets past
# an opponent is decided by that opponent's wall, and content/field.txt is the
# opponent's wave -- thinning it to a single grunt leaves leak cost dealt at
# exactly the 86, 112, 243, 56 and 39 gold it was already at, and cost
# efficiency at 0 to 5. It moves what a run concedes and nothing about whether
# sending is worth it.

income        168

#         purse  gold
#
# What a run's purse opens holding. Nothing has been earned when the first build
# phase stands, so a run that opened on nothing would have an opening round
# whose only affordable wave is the empty one -- ten waves with nine build
# phases in them. A hundred is enough to make the first round a round -- one
# tower and a wave behind it -- and like every number here it is a sweep target
# rather than a decision.
#
# IT IS DELIBERATELY SHORT OF A WAVE'S BASE. A run opens on an empty board, and
# opening it on a full base lets it buy most of its wall before anything walks:
# swept with this row moved up to the base, the roster wins between five and
# eight of every eight runs and the win column saturates again. Opening short of
# the wall is what the first round is about.

purse         100

#         band  percentile  percent
#
# The performance bonus, paid on top of the base in progressive percentile
# bands measured against the field. THE BANDS ARE NEVER NEGATIVE: performing
# below average earns a smaller bonus and never a penalty. Thresholds ascend
# strictly, the first is zero so every wave falls in a band, and no band pays
# less than the one below it. Nothing here moves gold between players: a wave
# is paid against the field's distribution and never against a named opponent,
# so it reads the same whether the field is one lobby or a population.
#
# THESE BANDS PAY, AND WHAT THEY ARE MEASURED AGAINST IS THE POOL A RUN WAS
# HANDED. A run prices ten of the pool's own rounds and reads its percentile off
# that spread, so the canned opponent field.txt describes is the distribution
# today and a stored population of real rounds is the same argument tomorrow.
# Retuning a threshold or a percentage here is an edit to these four lines and
# no compile.

band            0        0
band           50        5
band           75       10
band           90       20

#         health  gold
#
# The pool a run starts with, denominated in gold. A leaked creep costs health
# equal to its cost, one for one, so the exchange rate is legible without a
# table. Gold cannot repair it -- the pool is a clock.
#
# WHAT 1500 BUYS, MEASURED. A wave conceded whole costs what its sender paid for
# it, and the canned field sends a hundred gold a round, so the pool is some
# fifteen of those.
#
# THE MARGIN CLOSED WHEN THE ROSTER WAS SIGNED, AND IT REOPENED WHEN THE CLOCK
# CHANGE WAS FINISHED. The committed ten-round run in content/run-outcome.txt
# conceded 1251 and finished on 249 before the roster was signed; with the
# roster signed and the release cadence still at fifteen ticks it conceded the
# whole 1500 and died on the tenth wave, because a column three times denser in
# space saturates the towers and the canned field took about 153 a round where
# it had taken about 125. Dilating the cadence to forty-five undid that: the run
# now takes about 99 a round, survives all ten waves and finishes on 478.
#
# NOTHING HERE WAS TOUCHED TO ACHIEVE ANY OF THAT. This number has been 1500
# across all three measurements. Each time the run was committed as it played,
# because the alternative was retuning a number nobody had decided to retune in
# order to make a demo end more comfortably.
#
# WHICH LEAVES 1500 AS AN OPEN DECISION RATHER THAN A SETTLED ONE. Story 20
# wants the pool worth about three waves of average creep value, so that one
# deliberate concession is affordable and a second is a real decision. A wave
# conceded whole against an empty board costs 100, which makes this fifteen of
# them; something nearer 400 to 500 would restore the reading the story asked
# for.
#
# WHAT IT WAS WAITING ON HAS HAPPENED, AND THE MEASUREMENT IT WAS WAITING FOR
# HAS NOT. The taken column across the committed run is 100 90 65 30 33 32 32 32
# 31 33, which adds up to 478: it opens at a whole wave a round on an empty
# board and falls as the run's own build phases put towers up. So the pool is a
# resource the player manages now rather than a timer, which is what a value for
# it can finally be chosen against -- and nobody has chosen one. At 450 that run
# would have died in its tenth round, having spent the first three conceding 255
# while it built. This number, the opening purse and the income curve are one
# decision rather than three, and the base above is the one of the three that
# has now been measured against an empty opening board.

health       1500

# ---------------------------------------------------------------------------
# THE BUILD PHASE
#
#         slots  starting  per-anchor
#
# How many creep types a wave may carry. SLOT WIDTH IS DERIVED, NOT AUTHORED:
# a round's width is the starting width plus the per-anchor step once for every
# anchor at or before it. With anchors at waves 3, 6 and 9 that reads
# 2 2 3 3 3 4 4 4 5 5 across a ten-wave run, and moving an anchor moves the
# widths with it rather than leaving a second series behind to go stale.

slots           2         1

#         offering  ordinary  game-changers
#
# What the build phase puts in front of everybody. The same public selection
# each round, drawn fresh; on an anchor round the game changers join that
# round's ordinary options and one thing is taken from the merged list. The
# ratio between the two is what decides whether the merged menu is a real
# trade, which is why it is a number here rather than an argument.
#
# THE ORDINARY COUNT IS BOUNDED BY THE ROSTER. An option unlocks a creep and
# appears on a menu once, so an offering cannot be drawn out of fewer creeps
# than it carries options, and asking it to is refused rather than answered with
# the same creep twice. Three of the unit table's six walkers is half the roster
# on every menu, which leaves the draw enough room to be a draw; this rises with
# the roster.

offering        3         3

#         snapshot  free  gold
#
# Scouting. A run gets this many snapshots of an incoming wave for nothing and
# pays this much for every one after. The price is charged on data and never on
# compute: the rules themselves are exposed completely and always.

snapshot       10        25
