# The unit type table.
#
# ONE GLOBAL ID SPACE. Towers and creeps are the same kind of thing here, so
# an id is unique across every unit that has ever existed, is never reused,
# and is never an index into anything. A record that pins type 2 today still
# means this row in five years. The label beside it is for people reading this
# file and for error messages; nothing in the simulation branches on it, and
# renaming one does not move the content hash.
#
# THE GAPS AT 5, 6, 8, 9 AND 10 ARE PERMANENT. Five rows were retired when the
# roster was signed on 8 August 2026 -- wisp, bulwark, lancer, sniper and
# sieger -- and because ids are never reused, those five numbers stay empty
# forever. A stored record that pins one of them still means what it meant;
# there is simply nothing here to author against it. See docs/roster.md.
#
# INTEGERS ONLY, AND NO DECIMAL POINT. The parser refuses a '.' or a ',' on a
# data line before it even tokenises, so a designer typing 1.5 gets a load
# error rather than a float in the tick loop. Fractions are authored as the
# two integers they are made of, in units named by the column: thousandths of
# a hex, or ticks.
#
# FIELD ORDER IS WHAT THE CONTENT HASH FOLDS. Reindent a column, rewrap this
# comment or convert the line endings and the hash does not move, so no stored
# record is falsely retired. Change one number and it does.
#
# THE LAYOUT ROW BELOW SAYS WHICH COLUMNS THESE ARE. It comes before the first
# unit row because it is what says how to read one, and there is a reader
# branch per layout: a table written in the fifteen-column layout 1 still
# loads, folds under its own hash label and keeps the hash it always had, which
# is why the golden bundles pinned to one still replay. Adding or moving a
# column is a new layout and a new label, and a row whose field count does not
# match the layout it declared is refused rather than read against shifted
# fields.
#
# A NEW UNIT IS A ROW AND NEVER A COLUMN. That is what the layout row costs: a
# column is a format version, a hash label and every record made under the old
# one retired, and a row is a line. Layout 3 paid that price once, deliberately
# and for the last time before the map is measured: the five levers the roster
# was blocked on -- a target count, a radial shot, a timed slow, an aura and a
# second health pool -- are the nine columns below, and every unit in
# docs/roster.md that was waiting on one of them is now a row somebody has to
# write rather than a schema somebody has to widen.
#
# THREE OF THOSE FIVE TURNED OUT TO BE ONE MECHANIC. A radial shot, a timed
# modifier and a periodic aura are all a bubble that emits something,
# distinguished only by where it centres, how often it fires and what it
# carries -- so they are seven columns between them rather than seven each.
# The column count is identical either way; what collapsing them saved is three
# sets of rules with nothing holding them together. A Soldier's sweep is a
# bubble on himself with no period, a mortar's blast is one on what it hit, a
# Cryomancer's slow is one carrying speed with a duration, and a Captain's aura
# is the same thing with a period.
#
# THE TWO SHOT SHAPES ARE DISTINCT AND A ROW IS ONE OF THEM. A target count of
# n fires n shots at the n creeps nearest the exit and draws n damage rolls; a
# damage bubble is ONE shot drawing ONE roll, applied whole to everything it
# encloses -- no falloff, no friendly fire. How many numbers an attack takes
# off the dice stream is part of what every stored record replays through, so a
# row claiming both is refused at load rather than reconciled at the landing.
#
# WHICH UNIT FOLLOWS WHICH IS NOT IN THIS FILE. An upgrade edge is a row in
# content/upgrades.txt, which names two ids out of this table, and it is an
# annotation rather than a column for the reason above: a tier is its own id and
# its own row here, and the edge that joins two of them lives beside them. That
# file's edges fold into this table's content hash, so authoring one retires the
# records pinned to the roster before it exactly as retuning a number does.
#
# Ids ascend strictly down the file, which is what makes a duplicate a
# comparison against the row above rather than a lookup nobody performed. They
# ascend past the roles, so the towers and the creeps below interleave.
#
# EVERY DAMAGE AND HEALTH NUMBER IS AT THE TENFOLD SCALE. Multiplying both
# together leaves shots-to-kill where it was and buys resolution: armour and
# the type chart have ten times as many distinct results to land on across
# their range, which is what makes them tunable at all. It also widens the
# damage roll's range tenfold, so the seeded stream produces different numbers
# per shot and the golden trace beside these files is a different trace than
# the one the pre-scale numbers produced.
#
# NEITHER SIDE OF THE PURSE IS AUTHORED. BOTH ARE ARITHMETIC. There is one
# wallet and it buys both halves of the board, so both halves are priced in the
# same quantity by a rule rather than by judgement.
#
# EVERY WALKING ROW COSTS ITS EFFECTIVE HEALTH OVER A HUNDRED AND SIXTY. A leak
# charges health equal to what the creep cost to send, one for one, so what
# gold buys is health a defense has to spend to stop it -- and effective health
# is the pool times the armour multiplier, which is the one thing a defense
# cannot argue with. The type chart deliberately stays out of the price: every
# row and every column of the matrix is a permutation of the same three cells,
# so averaged over the three attack types every armour type is worth exactly
# the same, and an armour type that changed the price would be charging twice
# for a bet. Signing a creep is therefore signing health, speed and armour --
# the price follows and is never authored.
#
# EVERY PLACED ROW COSTS ONE GOLD PER FIVE DAMAGE A SECOND, TIMES THE BODIES A
# SHOT HITS. You pay for the health it removes, which is the same quantity the
# creep rule charges for, which is what lets one purse buy both. Signing a
# tower is therefore signing damage, cooldown and how many bodies it hits.
#
#   THE BODIES TERM IS THE TARGETS COLUMN, and until layout 3 it was a guess:
#   the rule read three bodies off anything delivering by projectile and one
#   off everything else, because no column said how many bodies a shot hit. Now
#   one does, so a row that fires three shots is priced on three and a row that
#   fires one is priced on one.
#
#   THE MAGE IS THE ROW THAT GUESS WAS PROPPING UP. It costs 92 gold, which is
#   three bodies' worth, and it fires one projectile at one creep -- its splash
#   has been a design statement in docs/roster.md and never a thing the
#   simulation did. Layout 3 is the first schema that could carry that splash
#   (a bubble on the target, radius 1000, payload damage) and this ticket
#   deliberately authored no such bubble and moved no price: what to do about a
#   row priced for three bodies that hits one is a design decision, and it is
#   written down here and asserted in ContentTests rather than tuned away.
#
#   THE TOWER CONSTANT IS TIED TO THE TICK RATE. "Five damage a second" is a
#   number about seconds, and cooldowns here are in ticks at thirty ticks a
#   second. The clock has already moved once. If it moves again, re-derive the
#   constant or every tower silently stops being based.
#
#   THE RULE PRICES NEITHER RANGE, NOR BUBBLE RADIUS, NOR SHIELD, NOR DURATION.
#   A one-hex tower and an eight-hex tower with the same damage cost the same,
#   and so do a blast that covers a hex and one that covers the board. That is
#   a known gap and not an oversight: the retired sniper is the row that missed
#   the rule worst, and it missed precisely because it was the longest-ranged
#   thing in the game. The silence is deliberate rather than forgotten -- see
#   docs/open-questions.md -- because a coefficient guessed against the
#   one-hex corridor is a coefficient priced against geometry that is going
#   away.
#
# THAT SAMENESS IS THE EXCHANGE RATE AND NOT A COINCIDENCE. A leak charging
# what the creep cost means the health gold buys is the leak rate and
# nothing else, so cost cancels out of it and a row is balanced by what it
# survives. See docs/research/cost-is-not-a-balance-lever-under-a-one-for-one-leak.md,
# which is also where the measurements are written down.
#
# WHAT THAT LEAVES A ROW TO DIFFER IN IS SHAPE. Speed, granularity, and which
# defense chews it. The five walking rows below span armour types and a factor
# of three in speed, so choosing between them is a read of the board rather
# than a lookup of which row was mispriced.
#
# THIRTY TICKS A SECOND, AND THE CLOCK SLOWED BY THREE ON 8 AUGUST 2026. Every
# duration here -- cooldown, windup, backswing, flight, dying -- was multiplied
# by three and every walking speed divided by it. Damage, health, range and
# every cost were left exactly where they were, so this changed how the game
# feels and no balance at all: a Minion crosses the forty-seven hex corridor in
# fifty-six seconds instead of eighteen, and a wave resolves in about three
# minutes instead of one.
#
# THE COMMITTED DEFENSE IS FOUR ARCHERS AND TWO MAGES, so it is a pierce line
# with a magic tail, and every health pool below is authored against what that
# line actually deals rather than against a raw roll. Pierce takes 70 against
# Armoured and 140 against Swift, so armour for armour an Armoured body stands
# about a quarter longer in front of it than its number says and a Swift body
# about a sixth less. Send the same two into an impact line and the two trade
# places, which is the whole of what the matrix is for.
#
# ONE ATTACK TYPE PER TOWER LINE. Soldier impact, Archer pierce, Mage magic --
# so you can read what a tower does to a body from which line it came from,
# rather than looking the row up. That is what moved the Mage off impact when
# the roster was signed, and it is why the three types are covered exactly once
# each rather than lopsidedly.
#
# THE MINION AND THE SKELETON SCOUT ARE THE PAIR THE COMMITTED WAVE SENDS, and
# they differ in speed, maximum hp and armour type -- and in the cost that
# follows from those -- and in nothing else, so that a later fast group catches
# an earlier slow group and unit ordering stops being theoretical.
#
# THE SCOUT IS EXACTLY TWICE THE MINION'S SPEED, and that is load-bearing
# rather than tidy. Two creeps are level for exactly one tick as one passes the
# other, and being level is the case the target-selection tiebreak exists for
# -- pick the creep furthest along, and the lower id if two are equal. With
# speeds that were merely different, the two would step past each other without
# ever landing on the same distance, the tiebreak would never once be
# consulted, and a rule nothing exercises is a rule nobody has checked. Paired
# with the wave releasing a Minion column and a Scout column on the same tick,
# this makes the pass a thing that happens repeatedly and visibly. The Skeleton
# walks at the Minion's speed exactly, so those three meet on whole ticks too;
# the Necromancer at 33 and the Warrior at 18 deliberately do not, because a
# pass that lands between ticks is the ordinary case and it needs to exist as
# well.
#
# THESE NUMBERS ARE TUNED TO A PARTIAL BREAK. Against the committed defense and
# the committed wave, seventeen of forty creeps get through -- a little over
# two fifths -- across a hundred and eighty-nine seconds. That is the point of
# the tuning and not a
# coincidence: a defense that holds tells you nothing when it changes, and a
# defense that collapses tells you nothing either. A partial break means the
# leak count is a number a person can watch, and the golden trace beside these
# files is the run that produced it.
#
#      id  label             role    maxHp  speed  range  cooldown  windup  backswing  dmgMin  dmgMax  delivery    flight  dying  cost  attack  armour    armourValue  shield  targets  bubbleRadius  bubbleOrigin  bubbleAffects  bubblePeriod  bubblePayload  bubbleMagnitude  bubbleDuration
#
# role     : moving (walks the corridor) | placed (stands where it was put)
# maxHp    : zero means the unit has no health pool and cannot be damaged
# speed    : thousandths of a hex per tick
# range    : thousandths of a hex
# flight   : ticks a projectile spends travelling; zero unless delivery is projectile
# dying    : ticks spent dying, so seeking into a death shows a death
# cost     : gold, and the health a leak of this creep costs one for one
# attack   : pierce | impact | magic, and none for a unit that never attacks
# armour   : swift | armoured | arcane, and none for a unit with no health pool
# armourValue : percent of base effective health added per point; none carries zero
#
# The nine columns layout 3 added:
#
# shield   : a pool that absorbs first and RAW -- armour and the type chart do
#            not touch it, overkill carries through to health, and it does not
#            regenerate. Zero is none, and a unit with no health pool may not
#            carry one
# targets  : shots per attack, each with its own damage roll, taken
#            nearest-to-exit first. 1 is an ordinary single shot
# bubbleRadius : thousandths of a hex, read as a SPHERE -- height only ever
#            costs a radius, which is what stops a bubble on a cliff blanketing
#            the board. 0 is the target alone; none is no bubble at all, and
#            then the six columns after it carry none and zero. THE TWO ZEROS
#            IN THIS FILE ARE DIFFERENT: a range of 0 is no reach at all,
#            because the range column has no other way to say so, and a bubble
#            says so with a word instead -- which is what frees its zero to
#            mean something
# bubbleOrigin : self (a sweep, centred on the emitter) | target (a blast,
#            centred on what the shot hit). A radius of 0 wants target: the
#            emitter's own hex is the one place nothing that walks can stand
# bubbleAffects : friend | enemy
# bubblePeriod : ticks. 0 fires with the attack; a positive value pulses on its
#            own, which is the whole of what makes a bubble an aura
# bubblePayload : damage, or one of speed, cooldown, armour, shield. RANGE IS
#            NOT A LEGAL PAYLOAD and is refused by name: coverage is
#            intersected with the route once, at load, and a payload that moved
#            a range would drag that back into the tick loop
# bubbleMagnitude : a percentage, for every payload that is not damage. A
#            damage bubble carries the attack's own roll, so it authors zero
#            here, and a slow is a negative speed percentage
# bubbleDuration : ticks the payload lasts. 0 is instant, which is what damage
#            always is -- and what a shield may be, because a pool is spent
#            rather than timed. Speed, cooldown and armour may not author 0: a
#            stat put back the tick it moved is a stat that never moved
#
# WHAT THE TICK LOOP RESOLVES TODAY IS ONE BUBBLE SHAPE: damage, against the
# enemy, fired with the attack, landing instantly. A period or any other
# payload is a per-creep timed effect, which is not built -- such a row parses,
# folds and stores, and a match built out of it refuses by name rather than
# standing on the board emitting nothing.
