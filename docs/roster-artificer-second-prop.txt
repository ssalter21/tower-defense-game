# THREE CANDIDATES, AND TWO OF THEM ARE ONE PICTURE. The ticket names a second
# socket, a combined prop, and the crate replacing the turret with the muzzle
# re-anchored. The first two are the SAME PICTURE -- two things on the tile --

# the game, or one authored model that is both. So this sheet draws the picture
# once, under the name of the question rather than of either mechanism, and
# which mechanism a signed candidate becomes is the sitting's.
#
# A '+' PUTS BOTH ON THE TILE WITHOUT THE ENGINE GAINING A SOCKET. The members
# are parented under one throwaway object at capture time and that object is
# what goes into the one BesideProp -- see BesideGroup.cs. Nothing in
# BesideProp, UnitArt, TowerView, MatchArt.asset or the generated scene moves,
# so this is a picture of the shipped view drawing something extra rather than a
# picture of a changed view.
#
# THE OFFSETS ARE THE CANDIDATE'S. A '~dx,dz' moves a member sideways then
# forward within the tile, in metres. The turret is 1.00 x 1.13 on the ground
# and the crate 0.57 x 0.49, on a 2.0 m tile -- so 0.65 sideways clears the
# turret's own footprint by 0.15 m and keeps the crate inside the tile. That is
# a starting layout for somebody to move and re-render, not a layout anybody
# signed: AGENTS.md rule 6 puts a layout on the human side of the line, and this
# file is edited and run again without an agent, a recompile or a commit.
#
# THE THIRD CANDIDATE IS ONLY HALF HERE, AND THIS IS THE HALF A SHEET CAN SHOW.
# "The crate replacing the turret with the muzzle re-anchored" moves where the
# shell leaves from, and a sheet is a still of a posed character with no shell

# only place an anchor can be seen at all.
